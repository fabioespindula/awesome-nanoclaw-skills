# Decision Lenses

Use these lenses selectively for complex `rethink` sessions. Do not turn every answer into a checklist.

## Peacetime / Wartime / Transition

- **Peacetime**: optimize for quality, learning, taste, optionality, compounding upside, and relationship health.
- **Wartime**: optimize for survival, speed, focus, trust preservation, cash/energy protection, and clear tradeoffs.
- **Transition**: identify the signals that change the operating mode.

Useful questions:

- What is the binding constraint?
- What must be protected first?
- What would become irresponsible if conditions worsen?
- What would become possible if pressure drops?

## Reversibility And Magnitude

Classify each decision by how hard it is to undo and how much it matters.

| Type | Handling |
| --- | --- |
| Low magnitude + reversible | Move fast; learn by doing. |
| High magnitude + reversible | Run a contained experiment. |
| Low magnitude + irreversible | Avoid unnecessary lock-in. |
| High magnitude + irreversible | Slow down; reduce blast radius first. |

## Constraint Stack

Find the true limiting factor. Many bad plans optimize a non-binding constraint.

Common constraints:

- time;
- money;
- attention;
- energy;
- trust;
- distribution;
- talent;
- reputation;
- health;
- regulatory risk;
- relationship load;
- technical debt;
- switching cost.

## Assumption Ledger

Separate assumptions by evidence level.

- **Known**: directly observed or measured.
- **Likely**: supported by repeated signals.
- **Speculative**: plausible but unproven.
- **Borrowed belief**: copied from someone else's narrative.
- **Wish**: emotionally attractive but weakly evidenced.

Plans usually break where "wish" is treated as "known".

## Alternative Shapes

Generate alternatives that are meaningfully different.

- **Do nothing yet**: wait intentionally and define the signal that changes the decision.
- **Small reversible test**: learn cheaply before committing.
- **Focused version**: solve the narrowest valuable problem.
- **Ambitious version**: build toward the larger opportunity.
- **Partnership/path-of-least-resistance**: borrow distribution, trust, capital, or capability.
- **Exit/cut**: stop investing and preserve capacity.

## Failure Modes

For product and company decisions:

- no real demand;
- wrong buyer/user;
- no distribution;
- overbuilt first version;
- trust failure;
- support burden;
- team distraction;
- unclear success metric;
- platform dependency;
- timing mismatch.

For technical decisions:

- silent failure;
- migration risk;
- poor observability;
- rollback gap;
- performance cliff;
- security boundary leak;
- brittle integration;
- untested edge case;
- future extension blocked by current shortcut.

For personal/life decisions:

- energy debt;
- money runway;
- loneliness or support network loss;
- identity mismatch;
- family/relationship strain;
- underestimated logistics;
- irreversible timing;
- decision made to escape discomfort rather than move toward a clear value.

## Recommendation Quality

A useful recommendation should say:

- what to do;
- what not to do yet;
- why now;
- what would change the answer;
- how to make the next step reversible when possible.
